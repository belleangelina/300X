# 300X 应用内升级与非阻塞登录设计

状态：待实机验收（未成为权威规范）
日期：2026-08-12
适用分支：`main` / V1

本文记录应用内升级及其前置的登录入口调整。在目标平台完成实际路径验证前，
`docs/spec/yamibox-v1.md` 仍是唯一权威规范。实机验收通过后，应同步修改仓库全部
相关文档，并将本文转为已批准的权威规范。

## 1. 目标与范围

- Android 支持后台检查、应用内下载、SHA-256 校验和调用系统安装器升级。
- Linux 和 iOS 支持后台检查，并在系统浏览器下载对应产物；应用展示 SHA-256，
  但不宣称已经校验浏览器下载的文件。
- GitCode 官方镜像优先检查，GitHub 作为备用检查源。
- 更新弹窗允许用户选择 GitHub 直连或国内下载。
- 国内下载默认使用项目维护者控制的 GitCode 官方镜像，并允许在设置中改为自定义
  GitHub 前缀代理。
- 登录页不再阻塞应用启动；未登录或会话失效时保持主界面结构与视觉效果一致。
- Git 标签触发 GitHub Actions 构建三个平台，并将相同发布内容同步到 GitHub 和
  GitCode。

本期不实现强制更新、系统通知栏下载、断点续传、Linux 原地替换、iOS 签名或安装、
更新清单独立数字签名。

## 2. 发布源与信任边界

主仓库：`https://github.com/belleangelina/300X`
国内官方镜像：`https://gitcode.com/belleangelina/300X`

两个正式 Release 使用相同标签、说明、安装包和 `update-manifest.json`。应用仅识别：

- 正式版本，忽略草稿与预发布；
- 构建号严格大于当前应用构建号；
- 清单结构完整且平台产物唯一；
- 大小为正整数，SHA-256 为 64 位十六进制字符串；
- 下载 URL 的主机与所声明发布源相符；
- Android 包下载完成后，文件大小和 SHA-256 都与清单一致。

本期不对清单额外签名。GitCode 是项目维护者控制的官方发布镜像；自定义公共代理的
剩余风险由用户选择承担。Android 仍由固定 APK 发布证书提供系统级更新身份校验。
Release 构建缺少正式签名配置时必须失败，禁止回退 debug 签名。

## 3. 更新清单

每个正式 Release 最后上传 `update-manifest.json`。建议结构如下：

```json
{
  "schemaVersion": 1,
  "versionName": "1.0.8",
  "buildNumber": 11,
  "releaseNotes": "更新说明",
  "publishedAt": "2026-08-12T12:00:00Z",
  "artifacts": [
    {
      "platform": "android",
      "variant": "arm64-v8a",
      "fileName": "X300-v1.0.8-android-arm64-v8a-release.apk",
      "size": 123,
      "sha256": "...",
      "githubUrl": "https://github.com/...",
      "gitcodeUrl": "https://gitcode.com/..."
    }
  ]
}
```

`artifacts` 包含 Android universal、Android arm64-v8a、当前 Linux 构建架构和未签名
iOS IPA。Android arm64 设备优先选用 arm64-v8a 包，其它设备使用 universal 包。

应用不依赖 Release 网页结构。检查入口固定为两个官方发布源的最新正式版清单；
自定义代理只把 GitHub 安装包 URL 拼接为：

```text
<规范化代理前缀><完整 GitHub URL>
```

代理前缀必须是 HTTPS 根地址，保存时补齐结尾 `/`，不允许用户名、密码、查询参数或
片段。

## 4. 检查策略

### 4.1 自动检查

- 默认开启，每 24 小时最多开始一次。
- 首页先显示，登录恢复和页面操作均不等待更新检查。
- 按 GitCode、GitHub 顺序检查；单个源连接超时 5 秒，总请求超时 10 秒。
- GitCode 超时、连接失败、无正式 Release、缺少清单或清单无效时尝试 GitHub。
- 两个源都失败时静默结束，不改变最后成功检查时间，使后续启动仍可重试。
- 成功确认“无更新”或取得有效新版本后记录检查时间。
- 自动检查关闭时不发起请求；重新开启不会清除已忽略的具体版本。

### 4.2 手动检查

“关于 APP”的版本号下方提供“检查更新”。点击后显示局部加载状态：

- 已是最新版：提示“当前已是最新版本”；
- 两个源都失败：显示简短错误和重试入口；
- 发现更新：显示统一更新弹窗；
- 不受自动检查开关或已忽略版本限制。

### 4.3 弹窗时机

自动检查结果暂存，只在漫画、小说或个人中心主页面显示。登录页、阅读器、设置页、
下载页或其它二级页面不弹出；返回任一主页面后再显示。应用在后台时不弹出，恢复前台
且位于主页面时再显示。选择下载后清除该次待处理结果；关闭或选择“忽略此版本”后记为
已忽略，不再自动提示，手动检查仍可显示该版本。

## 5. 更新弹窗与忽略策略

弹窗展示版本、更新说明、安装包大小和平台提示，更新说明使用纯文本可滚动区域，不
解析复杂 Markdown。

操作顺序：

- 主操作“GitHub 直连”；
- 次操作“国内下载”；
- 文本操作“忽略此版本”。

关闭弹窗等同“忽略此版本”，记录远端构建号；同一或更低构建号以后不再自动提示，
更高构建号恢复提示。“永不提醒更新”仅位于“更多设置”，不放进更新弹窗。开启后关闭
全部自动检查，手动检查仍可用；再次开启自动检查仍保留已忽略版本。

设置中的国内下载源：

- 默认“GitCode 官方镜像”；
- 可选“自定义代理”；
- 自定义代理初始示例为 `https://gh-proxy.org/`；
- 用户可在“国内下载源”中直接切回 GitCode 官方镜像。

后台版本检查始终使用 GitCode、GitHub 官方源，与国内下载源设置无关。

## 6. 平台行为

### 6.1 Android

- 在应用缓存目录的 `updates/` 中下载。
- 目标文件名使用清单文件名；下载时追加 `.part`。
- 下载完成后校验文件大小和 SHA-256，再原子改名为 `.apk`。
- 同版本已校验 APK 可复用；下载新版本前删除其它旧 APK 和残留 `.part`。
- 进度弹窗可关闭，关闭后下载继续，并在主界面底部显示进度；应用进程退出后不保证
  继续下载。
- 支持主动取消；失败后只提供手动重试，不自动循环重试。
- 下载完成后提示安装。仅此时检查“安装未知应用”能力。
- 未授权时说明原因，由用户点击“前往设置”进入 300X 专属授权页；返回后复用已校验
  APK 继续安装。
- 使用 AndroidX `FileProvider` 临时授予系统安装器读取权限。
- 新版应用下次启动时删除低于当前构建号的旧安装包；未完成的 `.part` 留到再次选择
  更新时清理，不实现断点续传。

### 6.2 Linux

“GitHub 直连”或“国内下载”均使用系统浏览器打开当前架构 `.tar.gz`。弹窗展示并允许
复制 SHA-256。应用不下载、不替换正在运行的程序，也不宣称已验证浏览器保存文件。

### 6.3 iOS

“GitHub 直连”或“国内下载”均使用系统浏览器打开未签名 IPA。弹窗展示并允许复制
SHA-256，并显示：

> iOS 安装包下载后无法直接安装，需要自行签名，或在受支持的设备上通过 TrollStore
> 安装。

应用不提供签名、TrollStore 兼容保证或安装能力。

## 7. 非阻塞登录

- 应用启动后立即进入 `HomeShell`，默认显示漫画区。
- 登录状态在后台恢复；恢复期间不使用全屏加载页覆盖主页。
- 未登录时漫画与小说保留现有标题栏、页签、底部导航或宽屏导航，内容区使用现有空
  状态视觉，显示“登录后查看漫画区/小说区”和“登录”按钮，不发起需要登录的目录请求。
- 个人中心使用未登录头像与“登录”文案；点击头像或登录入口打开可返回的登录页。
- 登录成功后关闭登录页，停留在原主入口，并自动加载或重试当前内容。
- 会话失效不强制跳转；与首次未登录使用相同空状态，仅文案改为“登录状态已失效，请
  重新登录”。
- 本机阅读历史和已下载内容未登录时仍可访问；云端收藏等需要账号的入口点击后打开
  登录页。
- 登录、未登录、会话失效统一复用现有主题、空状态、按钮、间距、卡片和宽屏布局，
  不引入独立视觉体系。
- 更新检查与论坛登录完全独立，未登录用户同样能自动或手动检查更新。

## 8. 发布流程

### 8.1 本地入口

新增 `publish_release.sh`，只允许从干净且与远端一致的 `main` 发布。

```text
./publish_release.sh -v 1.0.8 [-b 11] (-m "说明" | -n notes.md)
./publish_release.sh (-m "说明" | -n notes.md)
./publish_release.sh --retry v1.0.8 (-m "说明" | -n notes.md)
```

- `-m/--message` 与 `-n/--notes-file` 必须且只能指定一个，空值无效。
- 指定 `-v`：版本名由用户决定，构建号默认递增，也可由 `-b` 指定更大值；脚本修改
  `pubspec.yaml`，创建 `chore: release vX.Y.Z` 提交，确认后推送提交和标签。
- 未指定 `-v`：不允许 `-b`，不修改任何文件，读取当前完整版本并创建、推送标签。
- 标签为 `v<versionName>`，推送标签触发唯一一轮 GitHub Actions。
- `--retry` 只在 GitHub 与 GitCode 都没有对应 Release 时允许，将失败标签重新指向
  当前已推送的 `main` 后再次推送；任一平台已有 Release 时拒绝复用版本。

### 8.2 GitHub Actions

- 推送 `v*` 标签触发正式构建发布；手动入口仅用于将已有 GitHub Release 补同步到
  GitCode，不重新构建或创建版本。
- 校验标签版本与 `pubspec.yaml` 一致。
- 并行构建正式签名 Android universal/arm64 APK、Linux tar.gz、未签名 iOS IPA。
- 严格校验 Android 版本、ABI 与固定发布证书；构建日志由 CI 保存，对话只报告摘要。
- 汇总产物大小和 SHA-256，读取本地脚本提交的发布说明，生成统一清单。
- 创建 GitHub Release，并使用 GitHub Secrets 中的 GitCode 令牌先快进同步镜像的
  `main` 和原标签，再创建相同 GitCode Release；令牌不进入仓库或安装包。
- GitHub Secrets 至少包含现有四项 Android 签名配置、固定证书摘要
  `ANDROID_CERT_SHA256` 和 `GITCODE_TOKEN`；任一缺失时发布失败，不降级处理。
- 两端均先上传平台产物，最后上传 `update-manifest.json`。客户端忽略缺少有效清单的
  不完整 Release。
- GitCode 同步失败时保留已成功的 GitHub Release 和标签；使用手动“仅同步已有
  Release”入口补齐。内容一致的同名附件跳过，不一致则失败，不静默覆盖。

### 8.3 历史回填

只回填 GitCode `v1.0.4`：复制 GitHub 同版本标题、说明及原附件并校验，不处理更早
版本，不发布本地 `v1.0.5` 至 `v1.0.7`，也不为 `v1.0.4` 补更新清单。该操作是一次性
发布维护任务；后续版本全部由正式工作流同步。

## 9. 验证与转正规则

开发闭环只运行本次改动直接影响的单元、Widget、静态和脚本检查，完整输出写入
`.artifacts/validation/logs/`。通过构建不等于功能完成，至少需要实机验证：

- Android 已登录、未登录、会话失效、arm64 下载、哈希校验、取消/失败/复用、未知
  来源授权和覆盖安装；
- Linux 后台检查、两条下载线路、浏览器打开和 SHA-256 展示；
- iOS 条件允许时验证检查、线路选择、IPA 浏览器下载和安装提示；
- GitHub 标签触发、三平台产物、GitHub Release、GitCode 镜像及失败重试；
- 自动检查忽略版本、永不提醒、24 小时间隔和手动检查覆盖规则；
- 窄屏、横屏宽屏、浅色和深色下登录空状态及更新弹窗视觉一致性。

只有用户确认实机验证通过后，才执行：

1. 将本文状态改为“已批准”，作为该功能的权威详细规范；
2. 修改 `docs/spec/yamibox-v1.md`，移除冲突的“不做应用内自动更新”和登录门禁描述；
3. 同步 README、构建/发布说明、测试说明及其它受影响文档；
4. 记录已验证平台、产物版本和仍未覆盖的平台限制。
