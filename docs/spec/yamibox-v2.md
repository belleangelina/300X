# 300X V2 设计规格

状态：产品方案已确认，开发中；阶段 A 仅完成部分 Linux 只读路径闭环，阶段 B/C 尚未完成，不作为 V2 或移动端完成声明  
基线：`feature/v2.0`，从当前 `main` 创建  
日期：2026-08-12

## 1. 目标

V2 在保留 V1 漫画、小说、阅读、下载、历史、设置和应用内更新能力的基础上，增加完整论坛体验，并重组主导航与收藏页面。

“完整论坛”的边界不是电脑网页，也不是 Discuz API 能返回的字段集合，而是普通账号登录后在百合会真实移动网页中可见、可进入并可完成的论坛能力。

V2 必须满足：

- 论坛核心浏览和高频操作使用 300X 原生 Flutter 页面。
- 页面信息层级、内容顺序、入口位置和操作流程以真实移动网页为基准。
- 视觉、控件、色彩、响应式布局和反馈方式继续使用 300X 原生设计。
- Android 和 iOS 是正式产品目标。
- Linux 只用于共享原生能力的闭环验证，不作为 V2 产品发布目标。
- 旧 `feature/full-forum` 分支只作为参考，不继承其范围、实现或完成状态。

## 2. 权威来源与冲突规则

V2 论坛开发按以下优先级判断：

1. 登录后的真实移动网页：功能边界、信息结构、操作入口、权限、动态表单和流程的唯一权威。
2. 当前 `feature/v2.0` 代码：V1 已稳定功能和数据兼容的实现基线。
3. 经真实移动网页验证的 Discuz Mobile API：只作为读取数据源。
4. `feature/full-forum`：仅供查找可能可复用的思路，不是需求或实现依据。

发生冲突时：

- Mobile API 与移动网页不一致，以移动网页为准。
- 电脑网页存在、移动网页不存在的能力，不纳入 V2。
- 旧分支与当前基线不一致，以当前基线为准。
- 本地推断与服务端返回不一致，以当前账号的服务端权限和表单为准。

不得仅凭 URL 中存在 `mobile=2` 就认定响应为移动页面。必须同时校验最终 URL、页面标识、结构特征和登录身份；服务器重定向到电脑页面时不得按移动能力登记。

## 3. 明确不做

V2 不实现：

- 电脑网页独有的功能或仅能从电脑首页发现的插件。
- 版主、管理员专属的审核、封禁、移动主题和后台管理能力。
- 自建服务端、后台轮询或 Android/iOS 系统级实时推送。
- Web 平台。
- Linux 内嵌 WebView。
- 为论坛单独复制一套网页皮肤。
- 把整个论坛降级为 WebView。
- 操作系统级分享；移动论坛自身提供的站内分享不属于此项。
- V1 未要求的阅读历史跨设备同步等服务端能力。

签到和其他插件不再预设为必做。只有当普通账号能从真实移动网页发现并完成对应流程时，才纳入能力清单；电脑网页入口不能用于扩大 V2 范围。

## 4. 平台与登录流程

### 4.1 平台定位

| 平台 | 定位 | 原生论坛 | 登录态 WebView | 发布验收 |
| --- | --- | --- | --- | --- |
| Android | 正式产品 | 完整 | 支持受控兜底 | 必须实机验证 |
| iOS | 正式产品 | 完整 | 支持受控兜底 | 必须实机验证 |
| Linux | 闭环验证 | 验证共享路径 | 不支持 | 不作为产品发布结论 |

Linux 上仅有 WebView 实现的入口不显示。使用系统浏览器只能作为人工排障辅助，不能计入功能完成。

### 4.2 启动与登录

V2 保持当前 V1 行为：

- App 先进入主界面，不把登录页作为启动页。
- 首帧后继续执行现有应用内更新检查。
- 未登录时，漫画、小说、论坛和收藏的在线内容显示登录提示。
- 用户从内容提示或“我的”账号卡片进入登录页。
- V2 不新增游客浏览模式；本文的移动网页基准均指登录后的页面。
- 已保存会话仍按当前逻辑恢复；会话失效时提示重新登录。

## 5. 信息架构

### 5.1 主导航

窄屏底部导航和宽屏 NavigationRail 固定使用四个入口：

1. 漫画/小说
2. 论坛
3. 收藏
4. 我的

默认进入“漫画/小说”。四个入口分别保留内部页签、筛选、分页和滚动状态。再次点击当前入口时，先滚动到顶部，再刷新当前可见页面；不得刷新隐藏页签。

继续沿用当前宽屏判定和约 450 px 主列表加右侧详情区的原生响应式结构。宽屏只是重新排列相同的原生组件，不采用电脑网页的信息结构。

### 5.2 漫画/小说

首个入口包含三个顶部页签：

1. 漫画区
2. 轻小说
3. 文学区

三者继续沿用 V1 的作品聚合、列表/网格、跳页、主题分类、最新/热度、详情和阅读器逻辑。V2 论坛开发不得降低现有目录解析、阅读进度、下载或封面行为。

### 5.3 论坛

论坛是独立主入口，包含移动网页实际提供的分区、版块、主题、楼层、搜索、写操作和社区入口。具体结构见第 6 节。

### 5.4 收藏

收藏是独立主入口，顶部固定三个页签：

1. 漫画
2. 小说
3. 全部

收藏页面的页面留白、内容宽度、列表密度、加载/空/错误状态和筛选触发区与漫画/小说首页统一，不沿用旧分支的独立卡片风格。

“漫画”和“小说”按作品语义聚合论坛主题收藏。“全部”显示论坛原始收藏，并提供与首页一致的分类筛选：

- 默认筛选为“全部”。
- 分类名称、顺序和可见性从移动收藏页面动态读取，不硬编码。
- 2026-08-12 的只读盘点可见主题、版块、群组、日志和相册等类型；这些结果只是当前快照，不是固定枚举。
- 若服务端没有真正的跨类型列表，客户端使用页面返回的分类链接分别分页，再把规范化结果合并为连续列表；不得猜测分类 URL。
- 同一漫画或小说源主题同时出现在聚合页和“全部”的原始主题分类中。
- 聚合页与原始列表映射到同一条服务端收藏关系；任一入口添加或取消后，其他入口同步更新。
- 异构的“全部”使用连续列表；漫画和小说仍可沿用作品列表/网格切换。
- “全部”中的用户空间目标只有在服务端返回严格同源移动资料 URI 和唯一正 `uid` 时进入原生个人资料；未知社区目标不猜路由。

### 5.5 我的

“我的”继续承担账号、阅读历史、下载、主题、设置、开源主页和关于页面。云端收藏迁移到独立主入口后，不在“我的”重复展示。

登录后的移动个人资料、本人主题/回复、好友、访客、通知和私信通过论坛或账号卡片进入原生页面；入口归属以减少重复为准，但必须能从移动网页对应的上下文到达。

## 6. 论坛页面与交互

### 6.1 论坛首页

- 从移动网页或与其验证一致的接口动态读取分区、版块和子版块。
- 保持服务端名称、层级、顺序、说明、统计和当前账号可见性。
- 不硬编码 fid 清单。
- 移动网页没有提供的电脑端聚合模块不进入首页。
- 搜索、收藏、消息和个人入口按移动网页的上下文关系放置，但使用 300X 原生导航组件。

### 6.2 版块主题列表

版块页展示移动网页实际返回的：

- 主题分类。
- 最新、热门、精华等筛选。
- 服务端分页和跳页。
- 当前响应中带精确移动个人资料 URI 的主题作者可进入原生资料页；资料 URI 必须与同一正 `uid` 绑定，缓存或模板漂移不能制造空入口。
- 公告、置顶、关闭、投票、精华等状态。
- 发帖权限和版块收藏入口。

分类、筛选变化后回到第 1 页。后续页通过服务端返回的分页地址加载，不自行拼出未经验证的 Discuz 参数。列表保留当前筛选、已加载页范围和滚动位置。

### 6.3 主题与楼层

- 显示全部可见楼层，不套用漫画/小说阅读器的楼主过滤或正文清洗规则。
- 保留 pid、楼层号、作者、头像、时间、编辑状态、引用、文本样式、表情、图片、链接、附件、点评、评分和权限提示。
- 点评与评分从当前移动主题响应转换为结构化只读模型并由 Flutter 原生组件展示，不向 UI 传递对应原始 HTML。评分明细入口只接受当前响应返回且 tid、pid、`mobile=2` 完整匹配的同源 URI；完整评分页在取得可靠移动模板契约前关闭解析，不以网页纯文本或通用 HTML 兜底冒充原生完成。
- 支持服务端分页、阅读顺序和精确 pid 定位。
- 内部 fid、tid、pid、uid 链接优先路由到 App 原生页面。
- 外域链接不携带论坛 Cookie，并交由系统浏览器处理。
- 主题被可靠识别为作品来源时提供“阅读模式”；从阅读器返回时恢复论坛位置。
- 作品详情和阅读器的“讨论”入口定位到对应 tid/pid，不合并多个原始主题的回复。

### 6.4 搜索

- 论坛搜索独立于漫画/小说作品搜索。
- 搜索表单、范围、分页和结果类型来自移动网页。
- 当前版块搜索保留 fid 上下文；全论坛搜索不伪造当前版块条件。
- 搜索历史如需本地保存，必须按账号隔离；V2 不引入服务端搜索历史。

### 6.5 通知、私信与个人空间

只要真实移动网页向普通账号提供对应路径，以下能力属于原生核心范围：

- 通知分类、未读数量、列表、精确主题/楼层跳转和服务端已读状态。
- 私信会话、分页、未读、发送和回复。
- 当前用户及其他用户的移动个人资料。
- 本人主题与回复。
- 好友、在线成员、访客和移动页面实际提供的互动入口。

不建设系统级推送。通知在登录完成、回到前台、用户刷新及相关写操作成功后同步。

### 6.6 原生视觉

- 论坛复用现有 `ColorScheme`、字号、间距、图标和明暗主题。
- 页面分组、标题层级、内容顺序和操作上下文参考移动网页。
- 版块和主题使用连续列表与轻分隔，不为每项创建厚重独立卡片。
- 楼层使用正文优先的连续流；低频操作进入更多菜单。
- 发主题、回复、编辑和私信使用独立全屏原生编辑页。
- 网页 CSS、背景图、桌面导航和固定像素宽度不进入 Flutter 页面。

## 7. 移动能力清单

### 7.1 纳入规则

某项功能只有同时满足以下条件才纳入 V2：

1. 普通账号能从真实移动页面发现入口。
2. 目标仍处于允许的百合会 HTTPS 主机。
3. 读取页或提交表单能在移动流程中到达。
4. 能明确判断权限、成功、失败和结果未知状态。

运行时按钮必须来自当前响应中的链接、表单或权限信息。不得根据用户组名称、旧能力清单或电脑网页入口显示操作。

### 7.2 2026-08-12 只读盘点基线

本次使用隔离临时会话完成登录和 GET 盘点，未执行论坛业务写入，未保存账号、Cookie、formhash、私信或帖子正文。已确认移动路径包含：

- 论坛首页、版块和子版块。
- 版块分类、最新、热门、精华和分页。
- 发主题入口及包含主题、正文、分类、标签和附件的动态表单。
- 主题分页、阅读顺序、回复、评分明细、主题收藏和站内分享入口。
- 全论坛/当前版块搜索表单。
- 主题、版块、群组、日志和相册等收藏分类入口。
- 通知、私信列表及私信发送表单。
- 个人资料、本人主题/回复、好友、在线成员和访客入口。

2026-08-13 又以只读 GET 复核了普通回复、楼层引用、编辑和评分入口。普通回复与引用回复均返回 `body#forum.pg_post` 下的标准 `form#postform`：入口楼层分别由 `reppost` / `repquote` 指定，表单用隐藏 `reppid`、`reppost` 交叉绑定，提交地址声明 `replysubmit=yes`。编辑入口精确携带 `fid/tid/pid/page/mobile=2`，编辑页同样是唯一 `form#postform`，提交地址为 `action=edit&editsubmit=yes&extra=&mobile=2`，目标和页码由唯一隐藏字段绑定。表单同时含两个同名 `Filedata` 文件控件；当前只登记为未验证附件能力，不选择、不上传、不进入正文 POST。评分代表性响应仍没有标准 HTML `<form>`。本轮没有执行业务 POST，回复与编辑的成功码和成功跳转契约仍未知，不能把 GET 表单存在写成真实写入已完成。

同日版块收藏盘点还确认了一个非典型合同：添加收藏的移动入口本身是 GET 即突变，响应没有确认表单；取消收藏才是 GET 确认页加 POST。探针在识别该副作用前意外新增两条版块收藏，随即停止所有网络请求且没有执行取消 POST。实现使用独立安全管线：添加 GET 前先原子写入 attempted 封存；取消先严格核对唯一确认表单、action 和原样 marker，再在 POST 前封存；opaque 字段仅用 trim 判空，提交时保留服务端原始值，隐藏 `referer` 只允许当前 uid 的只读 `type=forum` 收藏列表，不能转发同源写入口。两者只在完整遍历 `type=forum` 收藏分页确认目标状态后自动解除，未知结果保留封存并支持人工核对解除。添加入口的 `handlekey` 只要求是 fresh 页提供的单一非空 opaque 值并原样使用，不推断其与 fid/uid 的关系，也不写入缓存、封存、错误文案或日志。不得把版块收藏添加入口当作只读 GET，不得套用通用 GET 表单后 POST 流程，也不得继续自动探测。

同日继续以脱敏只读 GET 核对了收藏中的群组、日志和相册目标：群组版块入口最终落到同 `fid` 的移动版块页，群组分类使用服务端返回的版块列表和分页；日志正文下存在独立移动评论节点；相册返回元数据和图片节点。当前实现据此提供原生只读页面，日志与相册正文不落盘，外域媒体不携论坛 Cookie 或论坛 Referer。上述路径尚未进入 Linux App 实际操作，且没有执行评论、相册或群组相关写入。

### 7.3 能力台账

实现期间维护脱敏的能力台账，每项至少包含：

- 移动入口和页面类型。
- 读取或写入。
- 当前账号权限来源。
- 原生实现或 WebView 兜底。
- Android、iOS 和 Linux 的适用性。
- 自动化、只读真实站、受控写入和目标平台验证状态。

旧分支的 `forum_capability_manifest.dart` 不可直接迁移。新台账从本节规则和真实移动盘点重新建立；“代码已接入”与“平台已验收”必须是不同状态。

## 8. 数据模型与数据源

### 8.1 论坛领域模型

论坛主题和楼层使用独立于作品阅读器的领域模型。普通主题不得为了复用 V1 解析器而伪装成 `Work`。

核心稳定标识包括：

- 分区/版块：fid 和父子关系。
- 主题：tid、fid。
- 楼层：pid、tid、页码和楼层位置。
- 用户：uid。
- 收藏：服务端 favorite ID、类型和目标 ID。
- 私信：会话及消息的服务端稳定 ID。

作品与论坛通过来源 tid/pid 建立映射，不通过可变标题关联。

### 8.2 混合读取策略

读取使用最小混合方案：

- 已验证语义一致、字段稳定的版块/主题/楼层读取可以使用 Discuz Mobile API。
- 导航层级、筛选入口、分页地址、权限、动态表单及 API 缺失字段从移动 HTML 获取。
- API 返回的能力必须与同一账号、同一页面的移动 HTML 做契约测试。
- API 缺字段、模板漂移或语义冲突时降级到移动 HTML。
- UI 只消费规范化领域模型，不直接读取 JSON Map 或 HTML 节点。

不要同时维护两套会产生不同权限结论的完整仓库。API 是读取加速路径，移动 HTML 是语义和能力覆盖层。

### 8.3 解析约束

- 解析器按论坛首页、版块列表、主题楼层、收藏、搜索、通知、私信、空间和动态表单分开维护。
- 不提供允许 UI 任意填写 action 和字段的通用提交器。
- 解析容忍字符串数字、空数组/对象和移动模板的小范围漂移。
- 无法识别模板时显示明确错误，并允许 Android/iOS 用户选择受控论坛原页；不得把残缺结果标记为成功。
- fixture 必须人工最小化和脱敏，不提交真实页面快照或用户内容。

## 9. 会话、网络与安全

- 所有原生论坛请求共享受控客户端和账号会话。
- Cookie、论坛缓存、草稿、通知和私信按 uid 隔离。
- 论坛认证 Cookie 只发送给登记的百合会 HTTPS 主机。
- 外站资源使用不带论坛 Cookie 的独立路径。
- 日志过滤账号、密码、Cookie、formhash、验证码和认证参数。
- 仅幂等 GET 可有限重试；任何业务 POST 不自动重试。
- HTML 和 JSON 解析可放入后台 isolate；Cookie、数据库和取消状态留在主 isolate。
- 页面退出后，旧请求和旧解析结果不得覆盖当前状态。

## 10. 写操作

### 10.1 通用流程

每次写操作遵循：

```text
读取最新移动入口/表单与权限
    -> 原生填写或进入受控移动原页
    -> 用户明确确认
    -> 只提交一次
    -> 解析服务器结果
    -> 必要时读回确认
    -> 更新缓存并清理对应草稿
```

- 只提交表单实际声明的隐藏字段、动态字段、提交标记和用户输入。
- action、重定向和附件地址必须通过同源 HTTPS 校验。
- 提交期间锁定操作；页面重建、前后台切换和进程恢复不得重复 POST。
- formhash 或验证码过期时保留输入，刷新表单后由用户再次确认。
- 响应丢失时显示“提交结果未知”，先读回目标资源，不自动重发。
- 只有服务端明确成功或读回确认成功后才更新本地状态。
- 删除、举报等难以撤销的操作需要二次确认。

### 10.2 编辑器与附件

- 原生编辑器按移动表单显示主题、分类、正文、标签、签名、阅读权限等当前账号可用字段。
- BBCode、表情、链接和图片按移动端实际能力实现。
- 附件选择、限制、上传和失败恢复以移动表单返回值为准。
- 草稿保存结构化用户输入，不保存 formhash；恢复草稿后必须重新读取表单。

## 11. WebView 边界

Android/iOS 允许登录态 WebView，但只用于：

- JavaScript 依赖强、无法稳定原生化的移动插件。
- 复杂账号页面。
- 已登记的动态表单或原生解析失败后的明确兜底。

要求：

- 只允许登记的百合会 HTTPS 主机。
- 页面顶部明确标识“论坛原页”，提供关闭和刷新。
- 进入前同步 App 会话，退出后以论坛域 Cookie 快照回写并重新校验 uid。
- 原生到 WebView 通过平台 Cookie Store 写入可表达的 `Secure`、`HttpOnly`、`Expires`、`Max-Age` 与 `SameSite`；WebView 回到原生不得降低已知认证 Cookie 的安全属性。iOS 可读取完整属性；Android 系统接口只能读取 `name=value`，因此按进入前快照保守合并，新认证 Cookie 至少使用 `Secure + HttpOnly + SameSite=Strict`，同名多作用域无法唯一判定时失败关闭。WAF 脚本 Cookie 例外保留脚本可读且强制 `Secure`。
- WebView 登出或切换身份必须同步到原生会话。
- 返回后刷新受影响的收藏、通知、私信或个人状态。
- Android 原页的文件选择只允许通过系统文档选择器打开已有文件；拒绝保存和相机入口，只向 WebView 返回 `content://` 只读 URI，选择本身不得触发上传。
- 每个兜底能力登记原因和目标平台，不能以 WebView 存在为由长期保留空原生页面。

## 12. 缓存、离线与草稿

- 最近访问的版块、主题、收藏、通知摘要、私信会话和空间摘要可以按账号缓存。
- 离线只读回看必须标注缓存时间，不伪装为最新或完整数据。
- 离线不允许写操作，也不建立自动发送 outbox。
- 发主题、回复、编辑和私信草稿按 uid 隔离。
- 恢复网络、启动或回到前台不得自动发送草稿。
- 退出登录清理账号论坛缓存、Cookie 和论坛草稿；保留 V1 已下载内容和本机阅读历史。

## 13. 旧分支迁移原则

禁止合并或整体 cherry-pick `feature/full-forum`。

允许迁移单个实现的条件：

1. 当前 V2 确实需要该能力。
2. 已对照真实移动网页验证输入、输出和权限语义。
3. 已适配当前 `main` 的会话、数据库、更新功能和 V1 修复。
4. 有针对当前移动 fixture 的测试。
5. 迁移不会带入无关格式重排或大范围 V1 文件覆盖。

页面、旧 V2 规范、能力清单、完成记录和 Linux 验证结论均不可直接迁移。
